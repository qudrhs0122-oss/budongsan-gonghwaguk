# R-008 토스 인앱상품(광고 제거·체력 회복권) 성과 집계 이벤트
상태: 자동승인
게임: 서울아파트 토스 미니앱(toss-seoul) / 종류: 새 기능(측정)
부서: 💰 수익화팀 / 올린 날짜: 2026-11-24 / 관련: 개발팀 c76dcf5 (11/24)

왜:
- 11/24 개발팀이 토스 인앱상품 2종(광고 제거 2,970원 비소모품, 체력 회복권 5장 1,100원 소모품)을 넣었음. 매출은 토스 콘솔(사장님 로그인)에서만 보이고, **상점을 몇 명이 열었는지·어디서 막히는지는 지금 아무 데도 안 남음**.
- 상점 진입 → 구매 버튼 → 결제 완료 단계별 숫자가 있어야 가격·문구·위치를 실험할 수 있음.

무엇을 (개발팀, `toss-seoul/src/toss-iap.js`·`src/seoul/ui.js`):
1. 기존 `stat(ev, k)` 그대로 사용 (새 데이터 수집 없음, 개인정보 없음):
   - 상점 열기 `stat('iap_shop', 'menu'|'hpbtn')` (어디서 열었는지)
   - 구매 버튼 `stat('iap_click', 'noads'|'hp')`
   - 결제 완료 `stat('iap_done', 'noads'|'hp')` / 실패·취소 `stat('iap_fail', 'noads'|'hp')`
   - 회복권 사용 `stat('iap_use', 'hp')`
2. 주문번호·금액·이용자 식별값은 **보내지 않는다**(종류 이름만).

예상 효과: 직접 매출 없음. 다음 출근부터 "상점 진입률 × 구매 전환율"로 가격·위치 안건을 숫자로 낼 수 있음.

정책 위험: 없음 (측정만, 광고·결제 흐름 변경 없음, 개인정보 미수집).

크기: 소(1시간)

참고(수익화팀 의견, 개발팀 확인 요청 — 안건 아님):
- 체력 0 직전 '체력 회복권 5장 구매' 버튼은 이용자가 눌러야만 결제창이 뜨는 구조라 문제없음. 다만 같은 반기에 여러 번 뜨지 않게(한 화면 1개) 유지해 주세요 — 토스 틴즈 노출을 고려해 결제 권유가 반복되면 안 됨.
- 서울아파트에 순위표(랭킹)가 붙는다면, 회복권을 쓴 판은 랭킹에서 구분 표시가 필요(돈으로 순위 사는 구조 방지). 현재 서울아파트 코드엔 랭킹 없음 — 붙일 때 기억.
