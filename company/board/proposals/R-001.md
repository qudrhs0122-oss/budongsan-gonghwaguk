# R-001 서울아파트: 판 시작·챕터 도달·전면광고 표시 집계 이벤트 추가
상태: 자동승인
> ⚠️ **미구현 (11/24 수익화팀 코드 확인)**: 11/21 개발팀 보고엔 "구현완료"로 적혔지만 `src/seoul/ui.js`에 `stat('start')`·챕터·전면 표시 집계가 없음. 위 상태 줄의 "(자동승인 → 구현완료)" 안내 문구를 완료 표시로 읽은 것으로 보임 → 개발팀 다음 출근 때 구현 부탁. 끝나면 상태를 `구현완료`로.
게임: 서울아파트(첫 아파트) / 종류: 새 기능(측정)
부서: 💰 수익화팀 / 올린 날짜: 2026-11-20

왜:
- 지금 `/api/stat`에 남는 건 `ending`, `reward_click/done/free`, `share/share_done` 뿐이라 **판 시작 수가 없음 → 완주율(엔딩 ÷ 시작)을 계산할 수 없음.**
- 수익화팀 지침의 핵심 판단("완주율이 낮으면 광고가 잦은지 의심 / 높고 노출 적으면 보상형 확대")을 하려면 분모가 필요함.
- 전면광고(`turn_break`·`chapter_break`)는 3분 간격 제한 때문에 실제 몇 번 떴는지 모름 → 노출 추정이 부정확.

무엇을:
1. 새 판을 시작할 때 `stat('start', mode)` 1회 (mode = `hist`/`now` 등 기존 모드 키, 소문자·밑줄만).
2. 새 챕터에 들어갈 때 `stat('chapter', 'c' + 챕터번호)` (c2~c10). → 챕터별 이탈 곡선.
3. `showAd(..., true, tag)`에서 **실제로 adBreak를 호출한 경우에만** `stat('inter_show', tag)`. 3분 제한으로 건너뛴 경우는 `stat('inter_skip', tag)`.
- 이용자 정보·기기 정보는 보내지 않는다(기존 `stat()` 함수 그대로, 이벤트 이름만 추가).

어디를 고치나: `src/seoul/ui.js` (새 판 시작 함수, `cineChapter` 진입부, `showAd`의 inter 분기). 서버 `addStat` 정규식(`^[a-z_]{2,30}$`)에 그대로 맞음 → 서버 수정 불필요.

예상 효과: 직접 수익 0원. 대신 다음 출근(화요일)부터 완주율·챕터별 이탈·실제 전면광고 노출을 숫자로 볼 수 있어 R-안건 효과 검증이 가능해짐.

정책 위험: 없음 (광고 위치·빈도 변경 없음, 개인정보 없음, 화면 변화 없음).

위험: 하루 이벤트 키가 늘어남(챕터 9 + 태그 2~4 ≈ 15개) — `addStat`의 게임당 300키 제한 안쪽.

크기: 소(30분~1시간)
