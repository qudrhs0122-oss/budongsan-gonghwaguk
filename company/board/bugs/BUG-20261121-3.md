# 누구나 주소 한 번만 열면 회사 스레드 자동 게시 연결이 끊김 (/threads/delete, /threads/uninstall)
상태: 확인완료
심각도: 높음 (사이트 보안·운영)
게임: 사이트
출처: QA 최근 24시간 변경분 점검 (11/21, 커밋 2971595 스레드 자동 게시)
재현 방법: (운영 서버에서는 시험하지 않음 — 코드로 확인) threads.js handle()의 Meta 콜백 처리 부분이 요청 메서드·서명 확인 없이 연결 정보를 지움. 외부인이 연결을 끊을 수 있고, 계정 바꿔치기 방지 장치도 연결이 비면 무력해짐.
기대 결과: Meta 콜백은 POST + `signed_request`(앱 시크릿 HMAC-SHA256) 검증이 맞을 때만, 그리고 그 user_id가 S.conn.uid와 같을 때만 해제.
실제 결과: 인증 없이 해제됨.
수정 방향(개발팀): POST만 허용, signed_request 검증, uid 일치 확인. (비밀값은 서버 환경변수에서 읽기만, 저장소에 쓰지 말 것)
증거: threads.js 136~139행

## 개발팀 처리 (2026-11-21)
원인: threads.js handle()의 /threads/delete·/threads/uninstall이 메서드·서명 확인 없이 S.conn = null.
수정: POST만 허용(GET 등은 405), body의 signed_request를 앱 시크릿 HMAC-SHA256으로 검증(timingSafeEqual, algorithm 확인), 실패 시 400. 서명이 맞고 user_id가 연결된 계정 uid와 같을 때만 연결 해제. 비밀값은 기존처럼 환경변수에서 읽기만 함(저장소 기록 없음).
검증: 로컬 시험용 가짜 시크릿으로 GET→405, 잘못된 서명→400, 올바른 서명→200 확인. 운영 서버에서는 시험하지 않음.
커밋: ec8c9dd

## QA 확인 (2026-11-22)
→ **확인완료** (로컬 서버에서만 시험, 운영 서버·비밀값은 건드리지 않음). GET /threads/uninstall·/threads/delete → 405, 서명 없는 POST → 400, 가짜 서명 POST → 400. 연결이 끊기지 않음.
