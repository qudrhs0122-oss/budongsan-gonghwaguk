2. **이벤트 문구 다듬기**: events.js의 제목·본문·선택지 문구(숫자 효과는 그대로). 더 생생하고 현실 사례처럼.
3. **엔딩 문구**: endings.js의 엔딩 이야기(s)·조건 설명(d) 문구.
4. **임장 분석·단지 소개**: imjang.js, data.js의 tip 문구를 최신 사실로 갱신.
5. **부동산 공부 페이지**: `public/learn/`의 가이드 글 1편/주 새로 쓰거나 최신 제도로 갱신 (SEO 유입용, 출처 표기).
숫자·확률·조건 로직을 바꾸는 일(새 이벤트 추가, 밸런스)은 아래 기획안 → 승인 → 개발팀 구현.

3. 기획안 `board/proposals/P-번호.md` 1~3개:
   ```
   상태: 결재대기   (결재대기 → 승인/반려 → 구현완료)
   게임: / 종류: 새 이벤트 | 뉴스 | 엔딩 조건 조정 | 밸런스 | 새 기능
   왜: (근거 뉴스 링크 또는 QA 수치)
   무엇을: (구체적으로. 이벤트라면 제목·본문·선택지·효과 수치까지)
   어디를 고치나: (src/seoul/events.js 등)
   위험: (밸런스 영향, 실제 제도와 다를 위험)

   ```
